# Engineering

[Documentation](../README.md) › Engineering

These references explain how the app's feature contracts fit together and how
to implement them. They belong with the detailed app docs in the open source
repository, for contributors and their agents.

| Area | Reference |
|---|---|
| Process boundaries, modules and data flow | [Architecture](architecture.md) |
| Script representation and round-trip fidelity | [Fountain data model](fountain-model.md) |
| Tokens, controls, menus and appearance | [Interface design system](design-system.md) |
| Platform capabilities and file access | [Cross-platform behavior](cross-platform.md) |
| Network endpoints, reports and feedback delivery | [Services](services-and-feedback.md) |
| Builds, signing, updates and distribution | [Release engineering](release-engineering.md) |
| Contribution workflow and checks | [Contributing](../../CONTRIBUTING.md) |
| Documentation structure and citations | [Maintaining these docs](documentation.md) |
| Permanent requirement numbers | [Allocation register](requirement-register.md) and [withdrawn requirements](withdrawn-requirements.md) |

Operational details specific to the maintainer's machines and accounts must be
separated or generalized before publication. That must preserve the underlying
technical contracts. The [public documentation requirement](release-engineering.md#REL-119)
defines the required depth.
